每次换教室上课，都要重新输一遍账号密码

希沃白板默认不记住登录状态，教学一体机又是多个人轮流用。本程序把这一步省掉：在你的电脑上把账号存好，希沃需要登录时直接给出可点的头像。

默认流程
  1. 打开希沃白板
  2. 切到「账号登录」
  3. 输入账号
  4. 输入密码
  5. 等登录完成

密码记不住的时候，还得掏手机翻一遍。

装好本程序之后
  1. 打开希沃白板
  2. 点自己的头像

剩下的登录动作由本程序在后台完成，账号密码不需要现场输入。

具体步骤以你所用希沃白板版本的登录界面为准；头像数量就是程序里「正在生效」的账号。

它具体做了什么

一个常驻托盘的 Windows 小程序（C# / WPF，界面用 WebView2），只管一件事：让希沃的登录变得不用输密码。

多账号管理

「正在生效」区最多放 6 个账号，这些账号会直接出现在希沃的登录界面上，点谁登谁。其余账号留在「暂未生效」区，右键托盘图标就能一键切换，不用重新加账号。

填账号密码，或者用希沃 App 扫码登录一次。扫码方式不需要把密码交给程序。

一键检查每个账号的密码或扫码凭据是否还有效，失效的账号会标出来并写明原因。

你的账号数据只留在本机

这类工具最该说清楚的就是数据去哪了。下面是程序实际的做法，代码在 GitHub 上可以逐行核对。

密码怎么存
账号密码用 Windows 自带的 DPAPI 加密后写入本机配置目录，密钥绑定当前 Windows 用户，拷走文件也解不开。扫码凭据同样加密存放。
网关谁能访问
本地 SSO 网关只应答来自本机回环地址（127.0.0.1 / ::1）的请求。同一局域网里别的机器即使伪造 Host 头，也会被拒绝。
会上传什么
不上传账号数据。除了检查新版本时读取公开的版本信息，程序不会把你的任何本地内容发出去。

常见问题

会不会把我的密码上传或者泄漏？

密码用 Windows 自带的 DPAPI 加密后存在本机 %LOCALAPPDATA%\SeewoAutoLogin\config.json 里，加密密钥绑定当前 Windows 用户，把文件拷到别的电脑也解不开。程序没有服务器，也没有账号体系。

登录时，密码只会发给希沃自己的登录接口；本地 SSO 网关只接受本机回环地址的请求，同一局域网内其它机器拿不到账号列表和令牌。

需要管理员权限吗？

需要。快捷登录依赖两件事：把 local.id.seewo.com 映射到本机（改 hosts），以及在本机 24300 端口跑一个 SSO 网关。这两件事在 Windows 上都要求管理员权限。

程序非管理员启动时会自动申请提权；如果你拒绝 UAC，程序仍能打开，但希沃里的快捷登录可能不可用。开机自启用的是「最高权限计划任务」，所以开机时不会再弹 UAC 询问。

希沃白板更新后还能用吗？

程序不修改希沃白板的任何文件，只是应答希沃自己会去请求的本地 SSO 接口。所以希沃的常规小版本更新通常不影响使用。

但如果希沃调整了这套接口，就需要跟着适配。程序内置了版本检查，有新版本会在主界面提示；也可以在 GitHub 的 Releases 页面关注更新。

三个安装包该下哪个？

能联网就下 9 MB 的标准安装包，缺 WebView2 运行时会自动补装。教室电脑不能上网就下 215 MB 的离线包。不想安装、要放 U 盘里带着走，就用 37 MB 的免安装单文件。

不想用了，卸载干净吗？

卸载时会自动清掉 hosts 里 local.id.seewo.com 的映射，以及 %LOCALAPPDATA%\SeewoAutoLogin 下的配置、扫码凭据、日志和网页资源目录，并移除开机自启的计划任务。

希沃白板自身的文件从头到尾没有被改动，卸载后希沃回到你装之前的登录方式。
