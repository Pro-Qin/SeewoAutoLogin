# 界面文案（i18n）

界面上所有**用户看得到**的文字都在语言文件里，不在代码里。

## 文件在哪

| 文件 | 用途 |
| --- | --- |
| `Resources/i18n/zh-CN.json` | 简体中文（完整，改文案就改这里） |
| `Resources/i18n/en-US.json` | English（缺的键自动回退到中文） |

两个文件都是 `键: 文案` 的扁平结构，`_meta` 记录语言代码与显示名。

## 怎么改文案

直接改 JSON 右侧的值，保存后重新构建即可。**不需要动代码**。

```json
{
  "accounts.sidebar": "账号列表",
  "accounts.actRenew": "续期",
  "strings.DeleteConfirm": "确定删除账号「{0}」吗？"
}
```

- 带 `{0}` `{1}` 的是占位符，顺序对应代码里的参数，**不要删掉占位符**。
- 键名不要改：代码与页面上都按这个键取值。真要改名，全局搜索一次同改。

## 三层各自怎么用

1. **页面静态文案**（`frontend/index.html`）
   `data-i18n="key"` 标注文本，`data-i18n-title / -placeholder / -aria-label` 标注属性。
   启动时 `applyI18n()` 整页替换一次。没标注的文本保持 HTML 里的原文 —— 漏标不会变空白。

2. **前端动态文案**（`frontend/js/*.js`）
   用 `t('key')`，缺失时回退到第二个参数或键名本身。

3. **C# 侧文案**（`Strings.cs` 与界面代码）
   `I18n.T("key")` / `I18n.T("key", args)`。`Strings.cs` 里的属性已经全部改成 `I18n.T`，
   所以调用点仍然写 `Strings.EnterPassword` 即可。

## 加一门语言

1. 复制 `zh-CN.json` 为 `<locale>.json`（如 `ja-JP.json`），翻译值。
2. 改入口（目前 `App` 构造函数里固定 `I18n.Initialize()` 走 zh-CN）：
   传 `I18n.Initialize("ja-JP")`，或后续在设置页里做成下拉。
3. 缺失的键会回退到 zh-CN，不会因为没翻译完就出现空白。

## 什么**不在**语言文件里

- 诊断日志（`WriteDiagnosticLog`）与异常消息：给排查问题的人看的技术描述，
  跟着代码走更可靠，翻译反而会把错误码、字段名改坏。
- 协议正文（`Resources/terms.txt`）：法律文本单独维护。
- 品牌名 `SeewoAutoLogin`：不翻译。
